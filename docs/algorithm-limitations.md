# Algorithm Limitations

PolyMerge's current multi-drug candidate generation and optimization is a research baseline.

## Current behavior

- Candidate drugs are derived from represented knowledge-graph treatment relationships.
- Candidate sets are generated by enumerating drug combinations up to the configured maximum drug count.
- Hard contraindication rules run before optimization. Rejected candidate sets are excluded from greedy selection.
- Greedy optimization prioritizes disease coverage, then compact candidate sets, using the available graph-derived evidence.
- Ranking uses deterministic fields such as coverage, confidence, and candidate count.

## Limitations

- The optimizer does not find the clinically safest or clinically optimal polypill.
- Coverage means represented knowledge-graph treatment coverage, not clinical efficacy.
- Hard safety rules are deterministic and incomplete. Passing the hard filter is not a clinical safety guarantee.
- No learned DDI model is implemented in this baseline.
- No learned synergy model is implemented in this baseline.
- Sprint 3 supervised labels describe represented `CtD` rows in the selected
  dataset and sampled lack of represented `CtD`; they are not clinical truth.
- Evidence preservation is provenance-oriented and should not be interpreted as regulatory or prescribing evidence.
- Greedy set-cover can miss globally better combinations because it makes local choices.
- Combination enumeration is bounded by configuration and may omit larger sets.
- Results require expert clinical, pharmacological, and regulatory review before any real-world use.
